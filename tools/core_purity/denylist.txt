# core-purity 규칙 2 — 코어(`server/atlas/**`)에 있으면 안 되는 게임 어휘.
# 근거: architecture-design.md §3.3(데모 게임 최소 집합) · §14(코어/계약/게임 3층) · §15.4(게이트).
#
# 🔴 이 목록은 지금 짧다. 데모 게임 콘텐츠가 아직 하나도 없기 때문이다.
# 🔴 목록이 짧다는 사실이 "코어에 오염이 없다"를 뜻하지 않는다 — 이 구간에서 "검사 통과"는
#    "시드한 6개 용어가 없다"는 뜻뿐이다. §3.3 에 항목을 추가할 때 그 어휘를 여기 같이 넣지 않으면
#    이 게이트는 조용히 낡은 어휘만 지키는 껍데기가 된다(§15.4).
#
# 형식: 한 줄에 용어 하나. `#` 로 시작하는 줄과 빈 줄은 무시한다.
#       매칭은 대소문자 무시 **부분 문자열**이다 — `boss_id` · `ApplySkillDamage` 처럼 게임 어휘가
#       실제 코드에 나타나는 형태를 잡기 위해서다. 대가로 `mob` 은 `mobility` 도 잡는다.
#       거짓 양성이 나면 그 용어를 목록에서 빼는 것이 답이지, 매칭을 느슨하게 하는 것이 아니다.
#
# 🔴 일부러 넣지 않은 §3.3 어휘와 그 사유(부분 문자열 매칭이라 더 크게 물린다):
#   move      — `std::move` · `remove` 가 코어 전역에 있다.
#   character — 3층 식별자(§6)의 코어 개념이다. 게임 어휘가 아니다.
#   spawn     — `boost::asio::spawn` · `co_spawn` 이 코어 I/O API 다(§9).
#               게임 쪽 개념은 mob/monster 가 덮는다.
